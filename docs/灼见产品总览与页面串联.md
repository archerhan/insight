# 灼见 · 产品总览与页面串联

> 产品名：**灼见** —— 思想与立场的碰撞，为求真相针锋相对，直抒己见。
> 一句话定位：一个让观点接受检验、让讨论沉淀结论、让"被说服"被记录的平台。
> 形态策略：先做 Web 跑通流程并积累第一批种子用户；产品验证后、确定做移动端时，再拆前后端。

## 一、产品核心闭环

```
广场发现话题
   │
   ├─ 围观/阅读 ─→ 结论书（已收敛）或 对线（进行中）→ 导出/分享
   ├─ 参与 ─→ 对线视图：反驳挂红 → 未回应计时 → 采纳/击穿 → 结论书 vN
   └─ 发起 ─→ 发起话题 → 立场生长 → 处理未决 → 出结论书 → 现实揭晓
                                                  │
                                       立场时间线 / 判断力战绩 / 诚实记录
```

三种人在这里赢：

1. **看得准**：预测与裁定被现实验证；
2. **接得住**：回应挑战、让争论收敛；
3. **改得动**：被说服后公开认错并附证词。

## 二、技术形态与阶段

### 阶段 1：Web（验证期）

- Next.js（App Router）一体化：服务端组件渲染话题页利于 SEO 与分享；无需拆分前后端，一人即可维护。
- 树/图数据先落 PostgreSQL（递归 CTE 或邻接表 + 路径缓存），后续量大再上图数据库。
- 实时性要求（对线挂红计时、揭晓通知）先用 Server Actions / 轻量轮询，流量上来后再引 WebSocket。

### 阶段 2：移动端（跑起来之后）

- 确认核心留存指标后，再拆前后端：Next.js 保留为 Web/API（BFF），移动端独立客户端。
- 拆分的时机信号：移动端占比 > 40%、或需要独立推送/离线能力、或团队分工需要前后端并行。

## 三、页面地图（信息架构）

全局壳：顶栏 = 灼见 Logo + 导航（广场 / 我的战绩）+ 右侧（发起话题 CTA / 通知 / 头像）。

```
灼见
├── 广场（首页）
│     ├── 正在对线（热榜/最新）
│     ├── 最新结论书
│     └── 立帖为证 · 即将揭晓
├── 议题工作台（核心，一个议题三视图，可深链切换）
│     ├── 结论书视图（默认着陆 · 已收敛话题）
│     ├── 对线视图（默认着陆 · 进行中话题）
│     └── 论证地图视图（复盘/研究，局部邻域 + 时间轴）
├── 发起话题（三步向导：类型 → 主张与论据 → 规则与发布）
└── 我的战绩
      ├── 立场时间线（改换阵营证词）
      ├── 我的话题 / 我的裁定 / 我的押注（Tab）
      └── 徽章墙 + 信誉与权限
```

规划中：通知中心（挂红提醒、揭晓提醒、结论书修订订阅）、搜索与标签页、议题"即将揭晓"事件页。

## 四、议题页的默认视图规则

- 议题**已收敛**：默认落在结论书视图（先给结论，树作为证据）。
- 议题**进行中**：默认落在对线视图（焦点下钻，处理未决反驳）。
- 论证地图视图：随时可切，用于复盘与研究。
- URL 建议：`/topics/[id]?tab=conclusion|arena|map`，便于分享到指定视图。

## 五、核心用户旅程

### 旅程 A：围观者 → 读者

广场看到"要不要裸辞去大理开民宿？"→ 话题页默认结论书 → 读结论与关键分歧 → 展开未决反驳 → 感兴趣下钻到对线 → 立帖为证倒计时提醒 → 55 天后现实揭晓 → 结论书自动更新 v4。

### 旅程 B：有真实纠结的人 → 楼主

发起话题（选"我在做选择"）→ AI 拆解初始论点树 → 发布 → 围观者补充盲区/反驳 → 未决反驳挂红倒计时 → 楼主逐条回应、被说服则公开改换阵营（诚实 +1、证词留档）→ 采纳关键论据 → 出结论书 v1 → 现实审计。

### 旅程 C：争辩者 → 有战绩的辩手

从广场进入正在对线的话题 → 复述检验后挂上反驳 → 对方未回应则挂红计时 → 对方回应或被陪审确认击穿 → 论据被采纳进结论书（贡献 +1）→ 战绩沉淀到个人页 → 权重升高，获得陪审资格。
