## 一、设计基调

一句话：产品在视觉上应该像**"克制的判决书 + 高信噪比的控制台"**，而不是"吵架广场"。

参考坐标：

- **Linear**：灰阶层级、排版秩序、微动效（主要对标对象）；
- **Notion**：克制、内容优先；
- **GitHub Issue/PR**：状态、合并、修订的语义化呈现；
- **Kialo**：仅借鉴局部结构，不借鉴其视觉。

三条原则：

1. **文字就是 UI**：用灰度、字重、留白建立层级，不靠插图与装饰色。
2. **颜色是语义**：颜色只表达"论证状态"，不表达情绪；颜色永远配文字标签。
3. **复杂藏在交互里**：永不渲染整棵树；用焦点卡、面包屑、缩略图做渐进披露。

## 二、色彩系统（语义色）

所有颜色以 CSS 变量承载，深色/浅色各一套（`light-dark()` 跟随系统外观）。

| 语义 | 用途 | 浅色基调 | 深色基调 |
|---|---|---|---|
| 纸张底色 | 页面背景 | 暖白 `#f6f4ef` | 近黑 `#161619` |
| 表面 | 卡片/面板 | `#ffffff` | `#202024` |
| 次级表面 | 标签底/悬停 | `#f1eee7` | `#26262c` |
| 墨水 | 主文字 | `#23211d` | `#eae7e0` |
| 次级墨水 | 辅助信息 | `#6b675e` | `#a8a49b` |
| 边框 | 分隔 | `#e3ded3` | `#34343a` |
| 支持（Pro） | 支持方/支撑理由 | 绿 | 柔绿 |
| 反驳（Con） | 反对方/反驳 | 红 | 柔红 |
| 采纳（Merged） | 已进结论书 | 紫 | 柔紫 |
| 击穿（Refuted） | 论点失效 | 灰 | 灰 |
| 悬空（Orphaned） | 支撑链断裂 | 灰 + 虚线 | 灰 + 虚线 |
| 未决（Pending） | 挂红/待回应 | 琥珀 | 琥珀 |
| 带险（Risk） | 带未决风险关闭 | 橙 | 橙 |

规则：

- 大面积底色一律低饱和；高饱和只用于小面积语义标记（dot、chip、3px 色条）。
- 语义必须成对出现：色块旁有文字（"支持方""已采纳""未回应 5 天"）。
- 卡片左色条或顶部色条表达立场；状态用 chip；正文永远用中性色。
- 对比度满足 WCAG AA，次要文字不低于 11px。

## 三、字体与排版

- 字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`；ID/哈希/引用编号用等宽字体（`ui-monospace`）。
- 字重只用 400/500，层级靠字号与灰度而非加粗。
- 字号阶梯：议题标题 20–25 / 焦点主张 16–18 / 正文 14–15 / 辅助 12–13；数字使用 `tabular-nums`。
- 中文不斜体；主张一句话控制在两行以内，超出以"…"省略。
- 灰度三档：主文字（ink）、辅助（ink-2）、边框（border），让页面有呼吸感。

## 四、状态视觉语言

状态视觉与《裁判机制设计.md》的状态机一一对应：

| 状态 | 视觉表达 |
|---|---|
| pending | 半透明，等待程序检查 |
| active | 默认卡片 |
| challenged | 红色左侧条 + 计时 chip（3/7/14 天） |
| disputed | 琥珀色底 + "仲裁中"chip |
| responded | 恢复默认，附"已回应"小标 |
| refuted | 灰 + 删除线（可选），chip"已击穿" |
| 悬空（orphaned） | 淡显 + 虚线框，chip"支撑链断裂"，附"抢救迁移"入口 |
| moot | 归档弱化，chip"目标已移除"，不参与计分 |
| merged | 紫色高亮 + "已采纳"chip |
| collapsed | 更淡 + 可展开箭头（软删除，不销毁） |
| closed_with_risk | 橙色边 + "带险关闭"chip |
| superseded | 归档样式，标注"已被 vN 取代" |
| adjudicated | 带现实检验徽章（应验 / 破产 / 后悔） |

区分要点：**击穿 ≠ 悬空**。击穿表示"作为论据失效"，用灰 + 删除线；悬空表示"支撑的墙塌了，论据本身未必错"，用淡显 + 虚线。两者混用会误伤仍然为真的事实论据。

## 五、组件清单

1. **顶栏（全局壳）**：灼见品牌标识 + 主导航（广场 / 我的战绩）+ 右侧"发起话题"CTA + 通知 + 头像；当前页高亮。
2. **视图切换条**：结论书 / 对线 / 论证地图 三段切换（桌面可见）。
3. **语义 chip**：立场（支持方/反对方/主论点）、状态（已采纳/已击穿/未决…）、时间（挂红 N 天）、倒计时（距揭晓 55 天）。
4. **主张卡（焦点卡）**：头行（立场 chip + 状态 chip）→ 主张标题 → 作者行（假名 + 判断力分）→ 标签（≤3，其余折叠）→ 证据行（事实论据 N · 来源 N）→ 操作行（支持/反驳/标记跑题，或状态说明）。
5. **子论点卡**：左侧 3px 立场色条；内容 = 一句话主张 + 作者行 + 状态 mini-chip + "下钻"箭头；整卡可点。
6. **分歧对**（结论书用）：标题"分歧 N · 状态" + 左右两张论点卡（支持/反驳），形成直接对抗的对照。
7. **未决面板**：浅红底 + 红色左边框；内容 = 反驳原文 + 影响范围 + 倒计时 chip + CTA"去回应"。
8. **结论摘要**：紫色左边框卡片；小标"结 论（暂定）" + 结论正文 + 依据摘要。
9. **统计条**：4 个轻量数字（论点 / 已采纳 / 未决反驳 / 已受现实检验），无图标堆砌。
10. **用户行**：头像 + 假名 + 判断力分；徽章与等级不进正文，放个人页/悬停。
11. **输入条（对线）**：分段控件"支持这一点 / 反驳这一点" + 文本框 + 提示行；选"反驳"时提示复述检验规则。
12. **面包屑**：议题 → 当前论证路径，逐级可回跳；过长显示截断 + 省略。

## 六、三大视图

### 1. 结论书视图（默认着陆，服务"想知道结果"的人）

信息架构自上而下：面包屑 → 议题标题 + 状态 chip + 操作（订阅修订 / 分享 / 导出）→ 结论摘要 → 统计条 → 关键分歧（分歧对列表）→ 未决反驳面板 → 论证地图入口与导出 → 底部声明。

议题页默认视图规则：**已收敛 → 结论书；进行中 → 对线**；用户可随时在三个视图间切换。

桌面：主栏 + 右侧 292px 信息栏（话题信息 / 立帖为证 / 采纳依据 / 修订历史）。

移动：单列；右侧栏折叠为"话题信息"章节；状态 chip 换行。

示意稿：[结论书视图 HTML](../design/conclusion-book.html)

### 2. 对线视图（核心交互，服务"参与与围观"的人）

核心机制：**焦点下钻**——屏幕中央一张焦点卡，下方两栏（支持理由 / 反驳）；点任意子卡，它成为新焦点并展开其下一层；面包屑随时回跳。

交互规则：

- 一次只显示"焦点 + 直接相连一层"，深度不溢出；
- 状态颜色全程一致：绿=支持、红=反驳、紫=已采纳、灰=击穿/悬空、琥珀=未决；
- 输入条内置"支持 / 反驳"分段与复述检验提示（反驳必须先复述对方观点）；
- 后续可加"路径模式"：隐藏兄弟节点，只跟一条反驳链走到底。

示意稿（可点击下钻体验）：[对线视图 HTML](../design/duel-view.html)

### 3. 论证地图视图（规划中，服务"复盘与研究"的人）

低频但必要。原则：

- 只渲染**局部邻域**（一个节点 + 直接相连节点），全图仅以缩略图/大纲形式存在于侧栏；
- 支持按状态筛选（只看已击穿 / 已采纳 / 未决）；
- 支持时间轴模式：展示"哪条反驳让谁改了立场"，与立场时间线打通；
- 桌面三栏：左大纲（定位）、中局部图、右节点上下文。

示意稿（可点击节点重定焦点、切换"结构图 / 时间轴"模式）：[论证地图视图 HTML](../design/argmap-view.html)

## 七、动效与交互原则

- 动效只回答两个问题：**"我在树的哪里"**（下钻推进/返回）和**"什么变了"**（状态变更）。
- 下钻：焦点卡内容推进/回退，带方向感，时长 150–250ms；尊重 `prefers-reduced-motion`。
- 状态变更：击穿 = 灰化淡出；采纳 = 紫色描边点亮；挂红 = 计时 chip 更新（不闪烁骚扰）。
- 无装饰性动画、无循环动效、无"庆祝撒花"；让"收敛"本身成为最安静的仪式。
- 触控目标 ≥40px；卡片整卡可点；键盘可达，焦点样式用系统默认。

## 八、响应式与平台

- 桌面（≥1120px）：结论书可用"主栏 + 信息栏"；对线可用单栏焦点布局。
- 平板（920–1120px）：信息栏降为下方两栏网格。
- 移动（<680px）：一切单列；分歧对上下堆叠；统计条 2×2；操作按钮换行占满。
- 深浅色：`color-scheme: light dark` + `light-dark()` 变量，跟随系统。

## 九、可访问性与一致性

- 颜色永不单独承载含义：每个色块旁有文字或 icon；
- 状态变化用 `aria-live` 播报；使用语义化 HTML（真实 button/heading）；
- 组件全部收敛到 token：开发阶段以 CSS 变量落地，禁止在业务代码里写死色值；
- 卡片圆角 8–12px、无重阴影、1px 边框，全站统一。
